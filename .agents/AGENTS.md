# Правила разработки для агентов (AGENTS.md)

В данном файле собраны ключевые правила и архитектурные особенности проекта `production-schedule`, сформированные на основе опыта разработки и оптимизации.

## Общая структура и окружение
- Проект организован как монорепозиторий с независимыми папками `frontend` и `backend`.
- **Адреса и порты**:
  - Фронтенд запускается локально на порту `2626` (`http://localhost:2626`).
  - Бэкенд работает на порту `3000` (`http://localhost:3000`).
- **Сборка TypeScript**:
  - В бэкенде скомпилированные файлы должны строго сохраняться в директорию `dist/` (настройки `rootDir: "./src"` и `outDir: "./dist"` в `tsconfig.json`). Запрещено компилировать и фиксировать файлы `.js` в папке `src/`.

## Фронтенд (React & Сетка)
- **Стилизация**:
  - Используется строго **чистый CSS / CSS Modules**. Запрещено использовать Tailwind CSS и утилитарные UI-фреймворки.
- **Таблица / Сетка расписания**:
  - Используется `@tanstack/react-virtual` для виртуализации строк.
  - **Z-Index и Позиционирование**:
    - Липкая колонка дат (`.dateCell`) должна иметь `position: sticky; left: 0; z-index: 20`.
    - Липкий заголовок столбцов (`.headerRow`) должен быть над ячейками.
    - Пересечение липкого заголовка и липкой колонки дат (верхняя левая ячейка "Дата") должно иметь `z-index: 21`, чтобы перекрывать прокручивающиеся столбцы и строки.
  - **Работа с датами**:
    - Даты хранятся и передаются с бэкенда в виде сырых строк формата `YYYY-MM-DD`.
    - **ВНИМАНИЕ**: Избегайте парсинга дат через стандартный `new Date(string)` во фронтенде для сравнений, так как это вызывает сдвиги часовых поясов (timezone shifts) в зависимости от локали пользователя. Выполняйте сравнения и подсветку текущего дня напрямую по строкам формата `YYYY-MM-DD` с приведением к GMT+3.

## Бэкенд (Node.js, Express, Prisma)
- **База данных**:
  - В качестве СУБД используется SQLite (файл `dev.db`), работа через Prisma ORM.
- **Производительность SQLite**:
  - SQLite имеет жесткие ограничения на скорость последовательной записи из-за накладных расходов на коммиты транзакций и дисковые операции (FSYNC).
  - При выполнении каскадных изменений или множественных обновлений ячеек расписания **запрещено** использовать последовательный `await` для каждого обновления внутри цикла.
  - Всегда накапливайте массив операций обновления и выполняйте их пакетно с помощью `await prisma.$transaction(updates)`. Это повышает скорость работы с БД в 10–50 раз.
- **Связь сущностей в JSON**:
  - Структурированные данные смен хранятся в виде JSON-объекта в поле `data` модели `ScheduleDate`.
  - При удалении машины, сотрудника или проекта обязательно делайте каскадное обновление поля `data` во всей таблице `ScheduleDate` в рамках единой транзакции бэкенда.
