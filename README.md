# Production Schedule

Система управления производственным расписанием для кино- и рекламных студий. Позволяет администраторам вести расписание смен по нескольким параллельным проектам, а сотрудникам и водителям — видеть только свои смены через персональную ссылку.

---

## Быстрый старт

### Требования

- Node.js 18+
- npm 9+

### 1. Клонировать и установить зависимости

```bash
git clone <repo-url>
cd production-schedule

# Backend
cd backend && npm install

# Frontend
cd ../frontend && npm install
```

### 2. Настроить окружение бэкенда

Файл `backend/.env` уже содержит настройки для локальной разработки:

```env
DATABASE_URL="file:./dev.db"
JWT_SECRET="supersecret"
```

> ⚠️ В production обязательно замените `JWT_SECRET` на длинную случайную строку!

### 3. Инициализировать базу данных

```bash
cd backend
npx prisma db push    # Создаёт таблицы по schema.prisma
npm run seed          # Заполняет тестовыми данными (проекты, сотрудники, расписание)
```

### 4. Запустить

**В двух отдельных терминалах:**

```bash
# Терминал 1 — Бэкенд (порт 3000)
cd backend && npm run dev

# Терминал 2 — Фронтенд (порт 2626)
cd frontend && npm run dev
```

Открыть в браузере: **http://localhost:2626**

Войти как администратор (тестовые данные из seed):
- Логин: `Admin` (или то, что задано в `seed.ts`)
- Пароль: `admin123`

## Структура данных

### Расписание

Каждый день хранится как одна запись в таблице `ScheduleDate`:

```
date: "2026-07-15"
data: {
  "<column-id>": {
    cellType: "shift",
    staff:    ["<user-uuid-1>", "<user-uuid-2>"],   ← UUIDs, не имена!
    cars:     ["<car-uuid>"],                        ← UUIDs, не names!
    dayType:  "натура",
    options:  ["погрузка"],
    text:     "Иван Сидор [натура, погрузка]",      ← для отображения
    color:    ""
  }
}
```

Имена сотрудников и техники хранятся в базе как UUID и разрешаются в имена **динамически** при рендеринге. Переименование сотрудника или техники обновляет только запись в таблице `User`/`Car`, не трогая историю расписания.

### Типы ячеек

| `cellType` | Описание |
|------------|----------|
| `project_start` | Начало проекта. Ячейка закрашивается цветом проекта. |
| `shift` | Обычная смена. Содержит сотрудников, технику, локацию. |
| `warehouse` | Складская смена. |
| `relocation` | Переезд. |
| `day_off` | Выходной. |
| `sleep_off` | Отсыпной. |
| `stop` | Конец проекта. |

## Интерфейс администратора

### Сетка расписания (левая часть)

- **Строки** — даты (один день = одна строка). Месяцы сворачиваются кликом по заголовку.
- **Столбцы** — независимые съёмочные группы или рабочие процессы.
- **Клик на ячейку** — выделяет её. **Второй клик** — открывает форму редактирования.
- **Drag по ячейкам** — множественное выделение для copy/paste.
- **Cmd+C / Ctrl+C** — копировать выделенные ячейки.
- **Cmd+V / Ctrl+V** — вставить (вставка умная: не перезаписывает старт проекта).
- **Клик на дату** — прокрутка к сегодняшнему дню.

### Боковая панель (правая часть)

**Техника:**
- Список всей техники (формат: `🚗 Название`)
- `➕` — добавить новую технику
- **Клик** на технику — включает highlight (техника подсвечена в сетке, остальное затемнено)
- **🔗** — скопировать и открыть персональную ссылку водителя
- **✏️** — редактировать (при выделении)
- **🗑** — удалить (при выделении)

**Проекты:**
- Список проектов с цветовой маркировкой
- **Клик** на проект — открыть редактирование (имя + цвет)
- `➕` — создать новый проект

**Сотрудники:**
- Список сотрудников (только role=STAFF)
- Аналогичная логика highlight/ссылки/редактирования как у техники

**Нижняя панель:**
- 🎨 **Настройки дизайна** — настройка цветов для каждого типа смены
- ➕ **Добавить столбец** — добавить новую колонку в сетку

### Форма редактирования ячейки

Открывается двойным кликом по ячейке. Поля зависят от типа:

- **Старт проекта:** выбор проекта из списка + опциональный комментарий
- **Смена/Склад/Переезд:** выбор сотрудников (мульти), техники (чекбоксы), локации, опций
- **Выходной/Отсыпной/Стоп:** форма без полей, просто подтвердить тип

## Персональная ссылка (Staff View)

Каждый сотрудник и каждая единица техники имеет уникальный токен. Ссылка вида:

```
http://yourdomain.com/my-calendar?token=abc123def456...
```

**Что видит пользователь:**
- Полная сетка расписания в режиме просмотра (без возможности редактирования)
- Отображаются только колонки и дни, где есть его смены
- Для контекста видны также ячейки `project_start` и `stop` (без данных других сотрудников)
- Имя отображается в шапке

**Как скопировать ссылку:**
1. В AdminBoard кликнуть на сотрудника/технику (выделить)
2. Нажать кнопку 🔗 — ссылка скопирована в буфер + открыта в новой вкладке

## Проекты

Проект — это сущность с именем и цветом (например, `Реклама Nike` — синий). В сетке проект отображается как:
- Ячейка `project_start` — закрашена цветом проекта, показывает название
- Все ячейки между start и stop — имеют цветной glow-эффект по границе
- Ячейка `stop` — закрашена затемнённым цветом проекта, текст "СТОП"
- Заголовок столбца при скролле показывает название текущего проекта

При удалении проекта из справочника исторические данные сохраняются (ячейки остаются с последним использованным цветом).

## Темизация

В AdminBoard → 🎨 Настройки дизайна можно настроить цвета:

| Настройка | Описание |
|-----------|----------|
| Выходной / Отсыпной | Цвет фона для выходных дней |
| Обычная смена (Натура) | Цвет фона натурных смен |
| Смена (Павильон) | Цвет фона павильонных смен |
| Смена (Склад) | Цвет фона складских смен |
| Смена (Переезд) | Цвет фона переездов |
| Цвет свечения (Hover) | Цвет подсветки при наведении |
| Текущий день | Цвет выделения строки сегодняшнего дня |
| Размер шрифта | Размер текста в ячейках (10–24px) |

Настройки сохраняются в базе данных и применяются глобально для всех пользователей.

## Техническая информация

### Стек

**Backend:**
- Node.js + Express 5
- Prisma ORM + SQLite
- JWT (jsonwebtoken) + bcrypt
- TypeScript → компилируется в `dist/`

**Frontend:**
- React 19 + TypeScript
- Vite (dev: порт 2626)
- @tanstack/react-virtual (виртуализация строк)
- Axios (HTTP-клиент)
- CSS Modules (без Tailwind)

### Переменные окружения (backend/.env)

| Переменная | Описание | Пример |
|------------|----------|--------|
| `DATABASE_URL` | Путь к SQLite файлу | `file:./dev.db` |
| `JWT_SECRET` | Секрет для подписи JWT | Любая длинная строка |
| `PORT` | Порт сервера (опционально) | `3000` |
| `CORS_ORIGIN` | Разрешённый origin (опционально) | `http://localhost:2626` |

### npm скрипты

```bash
# Backend
npm run dev      # Запуск с hot-reload (nodemon + tsx)
npm run build    # TypeScript → dist/
npm run start    # node dist/index.js (production)
npm run seed     # Заполнить БД тестовыми данными

# Frontend  
npm run dev      # Vite dev server
npm run build    # Production сборка → dist/
npm run preview  # Предпросмотр production
```

### Prisma

```bash
npx prisma db push      # Применить schema.prisma (без миграций)
npx prisma studio       # GUI для просмотра/редактирования БД
npx prisma generate     # Регенерировать клиент (после изменений схемы)
```

## Известные особенности

- **Legacy данные** из Google Sheets импортированы с устаревшим форматом (без поля `cellType`, с именами в `staff[]` вместо UUID). Фронтенд корректно их отображает через автодетекцию.
- **SQLite** — для production рекомендуется переход на PostgreSQL (достаточно сменить `provider` в schema.prisma и `DATABASE_URL`).
- Файл `backend/prisma/dev.db` — не коммитить в git для production-серверов.
- Файл `backend/prisma/dev.db.backup` — автоматический бэкап перед миграцией данных.
