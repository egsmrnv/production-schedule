# Production Schedule

Система управления расписанием съёмочной группы — высокопроизводительное веб-приложение для планирования смен, выходных, техники и персонала по нескольким параллельным проектам.

## Возможности

- **Сетка расписания** — виртуализированная таблица (сотни дней, десятки столбцов без потери производительности)
- **Типы ячеек** — Старт проекта, Смена (натура / павильон), Склад, Переезд, Выходной, Отсыпной, Стоп
- **Проектный контекст** — каждый столбец содержит последовательность блоков проектов; активный проект «прилипает» к верху столбца при прокрутке. В сайдбаре перечислены проекты (глобальные сущности), а в сетке расставляются блоки этих проектов.
- **Редактор ячеек** — выбор персонала, техники, локации, дополнительных опций
- **Тема оформления** — настраиваемые цвета для каждого типа смены, подсветка текущего дня, изменение размера шрифта
- **Фильтрация** — мгновенная подсветка ячеек по сотруднику, технике или столбцу
- **Staff View** — персональный просмотр для сотрудника по одноразовой ссылке с токеном. Отображает полную сетку проектов, но безопасно фильтрует на сервере чужие смены. Доступно быстрое копирование ссылки через `🔗` в админ-панели.
- **Права доступа** — панель администратора защищена JWT-авторизацией.

## Технологический стек

| Уровень   | Технологии                                                         |
|-----------|--------------------------------------------------------------------|
| Frontend  | React 19, TypeScript, Vite, CSS Modules, `@tanstack/react-virtual` |
| Backend   | Node.js, Express 5, TypeScript, Prisma ORM                        |
| БД        | SQLite (легко мигрировать на PostgreSQL через Prisma)             |
| Auth      | JWT (Admin), Magic-link токены (Staff)                            |

## Быстрый старт

### Требования

- Node.js >= 20
- npm >= 10

### 1. Backend

```bash
cd backend
npm install

# Создать .env (если нет):
echo 'DATABASE_URL="file:./dev.db"' > .env
echo 'JWT_SECRET="замените_на_секрет"' >> .env

# Применить миграции и создать БД:
npx prisma migrate dev --name init

# (Опционально) Заполнить тестовыми данными:
npm run seed

# Запустить в режиме разработки:
npm run dev
# → http://localhost:3000
```

### 2. Frontend

```bash
cd frontend
npm install

# Запустить в режиме разработки:
npm run dev
# → http://localhost:2626
```

### Тестовые доступы (после seed)

| Роль          | URL                                    | Логин / Пароль |
|---------------|----------------------------------------|----------------|
| Администратор | `http://localhost:2626/admin`          | `Admin` / `admin` |
| Сотрудник     | `http://localhost:2626/my-calendar?token=<token>` | Токен из вывода seed |

## Производственное развёртывание

### Backend

```bash
cd backend
npm run build          # компилирует TypeScript в dist/
npm start              # запускает dist/index.js
```

Переменные окружения:

| Переменная     | Описание                          | По умолчанию       |
|----------------|-----------------------------------|--------------------|
| `DATABASE_URL` | Строка подключения Prisma         | `file:./dev.db`    |
| `JWT_SECRET`   | Секрет для подписи JWT-токенов    | `supersecret` ⚠️  |
| `PORT`         | Порт HTTP-сервера                 | `3000`             |

> **Обязательно** замените `JWT_SECRET` перед деплоем в продакшен.

### Frontend

```bash
cd frontend
npm run build          # собирает в dist/
# Раздавайте dist/ любым статическим сервером (nginx, Vercel, Netlify...)
```

Если API не на `localhost:3000`, замените `baseURL` в `src/api/client.ts`.

## Структура проекта

```
production-schedule/
├── backend/
│   ├── src/
│   │   ├── index.ts          # API-сервер (все эндпоинты)
│   │   ├── seed.ts           # Тестовые данные
│   │   └── importHtml.ts     # Утилита импорта из HTML (Google Sheets)
│   ├── prisma/
│   │   ├── schema.prisma     # Схема БД
│   │   └── dev.db            # SQLite (не коммитить в production)
│   └── .env
│
└── frontend/
    └── src/
        ├── App.tsx            # Роутинг: /login, /admin, /my-calendar
        ├── api/client.ts      # Axios-клиент + JWT-интерцептор
        ├── pages/
        │   ├── AdminBoard/    # Главная страница администратора
        │   ├── Login/         # Авторизация
        │   └── StaffView/     # Персональный просмотр (readOnly DataGrid)
        └── components/Grid/
            ├── DataGrid.tsx              # Сетка расписания (основной компонент)
            ├── CellSettingsModal.tsx     # Редактирование ячейки
            ├── DesignSettingsModal.tsx   # Настройки темы
            └── ColumnSettingsModal.tsx   # Управление столбцами
```

## API-эндпоинты

| Метод  | Путь                    | Auth   | Описание                              |
|--------|-------------------------|--------|---------------------------------------|
| POST   | `/api/auth/login`       | —      | Авторизация администратора, возврат JWT |
| GET    | `/api/schedule`         | Admin  | Все столбцы и даты расписания         |
| PUT    | `/api/schedule`         | Admin  | Сохранить данные одной даты           |
| POST   | `/api/columns`          | Admin  | Создать новый столбец                 |
| DELETE | `/api/columns/:id`      | Admin  | Удалить столбец + каскадно очистить данные |
| GET    | `/api/admin/staff`      | Admin  | Список сотрудников                    |
| POST   | `/api/admin/staff`      | Admin  | Добавить сотрудника                   |
| DELETE | `/api/admin/staff/:id`  | Admin  | Удалить сотрудника + очистить историю |
| GET    | `/api/admin/cars`       | Admin  | Список техники                        |
| POST   | `/api/admin/cars`       | Admin  | Добавить технику (обязательно 2 поля) |
| DELETE | `/api/admin/cars/:id`   | Admin  | Удалить технику + очистить историю    |
| GET    | `/api/settings`         | —      | Настройки темы оформления             |
| PUT    | `/api/settings`         | Admin  | Сохранить настройки темы              |
| GET    | `/api/staff/schedule`   | Token  | Расписание для сотрудника (по токену) |
